Base: `8f87323bf777d0d5f57574d9bdb2298b438cebe3`.

Normal [CI654](https://github.com/gl11tchy-team/sigil/actions/runs/39144923320)
ran test-only head `98b1637facf2b4c8285dc00dbec7fdebde3ab26b`. Production

`ca0f19ee10acea12f10394e2362b8e12bb0edaf8` had the expected base/head parents

The synthetic 10,000-row fixture made six typing calls while output advanced.
Each invoked a full-buffer read. Input callbacks took **98.439, 103.558,
101.326, 101.060, 97.504 and 98.180 ms**. A separately measured immutable
scan took **11.149 ms**. The new responsiveness assertion was the only
failure among 1,343 Swift tests in 113 suites. This was the reproduction,
not evidence that the implementation passed. No personal output was read.

## Implementation and identity

- Query edits coalesce for 80 ms. Their input callback neither walks terminal
  rows nor waits for matching. One pipeline captures immutable row/cell-map
  chunks on main, then constructs logical lines and scans in a detached
  user-initiated task. SwiftTerm objects never cross into that scan.
- Capture yields after at most 64 rows or a 2 ms cooperative budget, checked
  after each physical row. A single physical row can overrun that time budget;
  actual largest-pass timings are reported by CI. No text or cell-map
  truncation is introduced. A bounded 16,384-entry cache checks each line and
  next-line identity/generation before reusing a row; it does not cap search
  coverage. Every current buffer row is still captured.
  Each pass cooperatively yields; after 2 ms of accumulated snapshot CPU
  work, an explicit zero-tolerance timer gives the run loop a turn. Avoiding
  a coalescible timer after every cheap/cache-hit pass keeps progress bounded
  by useful work instead of hundreds of timer wake-ups.
- A query request and a buffer/layout epoch gate publication separately.
  Reset, reflow, alternate buffer, trim reset and beginning-identity changes
  invalidate older coordinates. Rows use the pinned SwiftTerm trim counter
  as an absolute anchor; selection rebases it to the current buffer.
- Continuous output requests another pass without repeatedly canceling the
  current one. Verified history and bounded live-row metadata checks allow
  partial progress while the live screen changes. Sorted match-index ranges
  are found by binary search; publication/navigation does not walk a huge
  match list on main. Pending/partial counts are explicitly marked as
  searching. After output settles, a complete snapshot supplies exact counts.
- Current selection endpoints and next-row stamps are checked again before
  assigning cells. The original Unicode folding, grapheme/wide-cell maps,
  soft-wrap matching and exclusive-end selection convention remain in use.
  Queued navigation applies to an accepted current result. A partial initial
  result does not scroll the viewport, and refresh retains the selected
  absolute match when it is still valid.
- Navigation within a partial result requires both origin and destination
  inside its contiguous verified history prefix, without wrapping. Navigation
  across live/unchecked rows or the end stays queued for a complete scan;
  partial counts continue to make progress. An unverified prior origin is
  retained as a preference, never replaced by a different partial hit.
  Explicit navigation adopts a visible partial hit as its origin, so verified
  history navigation does not require the first complete/quiet snapshot.
- Resize notifications reach Find independently of lifecycle activity.
  Async results update only the visible selected tab's Find bar. Count
  announcements wait for completion; closing or switching tabs clears state.

SwiftTerm is pinned to clean revision
`7691f85b222a67a66b58499e1b2647443cf0dda7` (1.18.0). Its public per-line
generation and trim APIs supply identity. Display dirty ranges are not used
as sole proof. History is outside the mutable live-screen region; the
capture excludes its wrap-dependent boundary, and structural changes
invalidate it. Tests exercise reset, history clear, resize and capped trim.
The generic `ScrollbackSearch` matcher and provider/PTY semantics are unchanged.

## Verification method and review findings

The final 10k fixture waits for the actual controller, checks its published
count/index against terminal rows, and records input latency, actual controller
scan duration/thread, snapshot work/duration and coalescing. A second capped
stream writes 400 rows while a main-actor heartbeat records scheduling delay;
it requires results before the stream ends, then exact settled behavior.
It also requires Previous to reach the preceding absolute row while the stream
is still active, without waiting for a first complete snapshot.
These are synthetic CI measurements, not OS keystroke or physical-device latency.
Stream and heartbeat timers request zero tolerance so timer coalescing is not
mistaken for main-actor processing delay. The 1.5-second first-progress deadline
is unchanged after CI656 exposed excessive per-pass timer latency.

Controlled scan gates cover changed/cleared queries, stale row contents,
resize and alternate/reset results. Other cases cover queued navigation,
trim rebasing, unchanged row reuse and existing Unicode/wrap/viewport
behavior. Gates after an initial completed scan check appended hits before
wrapping, an unverified previous origin, and navigation within verified
history before completion. A CI-only AppModel case checks visible-bar count
delivery and dismissal. Native execution is CI-only. The PR records actual final-head
compilation, test counts, timings, skips and any remaining blockers; this
methodology document does not claim a local native pass.

The automatic review of the test-only baseline reported the intentionally
failing assertion ([4307782384](https://github.com/gl11tchy-team/sigil/pull/188#discussion_r4307782384))
and correctly requested controller completion proof instead of relying on
the separate scanner ([4307782390](https://github.com/gl11tchy-team/sigil/pull/188#discussion_r4307782390)).
The production change and actual-controller assertions address those scopes;
acceptance and thread resolution remain for parent review.
