## Reproduction and implementation

With main's production files unchanged, the added Node regression observed zero
`chats` requests on opening the sheet instead of one empty-text request.
Chromium at 390×844 reached the same empty saved section. The
[before screenshot](rea-1204/before-chromium.png) contains only generated data.
WebKit's local baseline did not reach the sheet: its synthetic pairing stalled.
It is not counted as a reproduced product failure.

Opening or clearing search now requests recent chats through the existing
coalescing queue. A nonempty query replaces them with search results; clearing
returns to recents. Loading, empty, unavailable and partial results have distinct
text. Only an authenticated `Unknown action.` reply quietly hides the section.

Show more requests at most 40 rows, using the number of consumed rows as the next
offset. Provider/folder/native-ID identity deduplicates concurrent overlap and
retains distinct providers/folders; a later duplicate can update its title.
Reads stop after 400 consumed rows, oversized pages or a page with no new identity.
There is no automatic paging loop. The current `sessionOps` contract gates
continuation: indexed chat paging predates that capability (commits `eb5ed41`
and `1eb0c7a`); older hosts receive one bounded page. No Mac/protocol change is
required. Offset pagination cannot guarantee a complete snapshot while the Mac
list changes; reopening/searching starts a fresh read.

Publication and saved-row actions carry the query/sheet token, connection
generation/epoch, credential owner and reported Mac identity. Closing, changing
Mac/connection or beginning another pairing clears old rows. A queued saved open
also rechecks its context when its queue turn arrives. Coalescing updates the
page index together with the query, so an old page offset cannot follow new text.
Existing connection/challenge checks and command sequencing remain in force.
An additional regression reproduced a discarded in-flight read leaving the sheet
without a replacement after the page's fresh-state return refresh. The fix reloads
an open sheet after that fresh state; the new Node case fails before the fix.
