# REA-1206: web New session choices

Ticket: [REA-1206](https://linear.app/reasonable-glyph/issue/REA-1206/offer-worktree-model-and-new-project-choices-in-the-web-new-sheet).
Baseline: main `52e96e3d7d2eb2427826af57543338a11b8019d4`.

## Contract and scope

The New sheet selects a project and starts once with the provider's advertised
choices. Its existing fonts, tokens and rows remain the design reference. A
repository with `sessionOps` offers a 44px worktree switch. The per-project
`worktreeDefault` wins, including a home repository's false default; older project
records fall back to `startsInWorktree`, then the native phone's legacy true
fallback. An explicit toggle applies only to the selected project. Macs without
`options` retain one-tap project starts; without `sessionOps` the switch and New
project are absent and the sheet explains that the Mac applies its default.

Only a provider advertising `takesModel` gets Model and Effort. Both values must
belong to its Mac-advertised options. An empty selected `options.model` also
advertises CLI default even though it is absent from the named-model list; this
choice is preserved rather than silently replaced with the first named model. Provider
problems still disable starts. New project accepts only an advertised location
and the Mac's single-folder rule (trimmed, at most 80 UTF-8 bytes, no leading dot,
slash, colon or control characters). Existing-folder adoption is the existing
Mac command's behavior. A successful reply selects the returned exact folder;
a project-list refresh supplies current repository metadata before a switch is
offered. Creation never starts a session automatically.

No backend, wire format, worktree cleanup, credentials, path authorization,
deployment or installed app changes. REA-1225's attempt ownership and safe cleanup
remain authoritative. A dispatch reply is not proof of provider progress.

## Uncertain outcomes

The existing authenticated protocol correlates replies by connection challenge,
client nonce and sequence. It does not advertise a persistent start-attempt ID or
an outcome-query operation. A tab with a similar title, folder or arrival time
cannot identify a lost start. No such inference is added.

Before dispatch, one bounded pending marker with a random claim ID is atomically
claimed in this pairing’s existing IndexedDB record. Shared-origin browser
contexts use the same read/write transaction to check and claim it. Ticket
persistence preserves the stored marker, and settlement clears only the matching
claim; a stale page cannot erase another page’s pending start. A matching authenticated success or explicit
failure settles it. Failure to persist prevents dispatch. If the connection is
lost, times out, reloads, or supplies an unexpected project reply, the marker
blocks all further web creation and starts, including legacy shortcuts and
changed provider/project choices. Closing a sheet does not cancel a sent action.
Late replies from retired connections cannot settle it. A pending marker is
scoped to the existing pairing; explicitly forgetting/replacing pairing or
clearing site data is not a durable server-side idempotency mechanism.

For `createProject`, Check projects can reconcile the exact expected absolute
path against current authenticated project records, at most ten 40-row pages.
This proves that the intended folder is now an advertised project, including an
existing folder adopted by the Mac. Similar names or other paths do not count;
absence, truncation and connection replacement never prove failure. This check
sends no creation command. If it cannot find the exact project, the user must
inspect that folder on the Mac and web creation stays blocked.

For a lost `new` result, this protocol cannot establish an authoritative outcome.
New stays blocked across reconnect/reload. The sheet directs the user to inspect
Sigil's tabs and worktrees on the Mac and start further sessions there while the
result remains unresolved. A future recoverable start receipt is separate
protocol work; this ticket does not manufacture one or remove worktrees.
