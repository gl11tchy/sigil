## Behavior

- Canonical socket peer identity only; IPv4-mapped IPv6 shares IPv4's budget,
  and native IPv6 shares a /64. No forwarding header or boolean proxy flag is
  trusted. No verified proxy ingress rule was available to enable.
- Five-token allocation burst, refill one token per 12 seconds; twenty allocated
  live rooms and 20 open WebSockets per source. Connection admission precedes
  `handleUpgrade`; malformed/closed connections release reservations once. The
  room cap includes disconnected rooms in the existing five-minute grace, giving
  NAT/reconnect headroom while one source owns at most one fifth of global rooms.
- Preserve the global 100-room and 300-TCP ceilings. Source state has at most
  1,024 entries; fully idle entries expire after a minute. Capacity pressure also
  reclaims idle entries with full buckets, including closed connection-only
  entries. Occupied entries retain their counters, and freeing room slots
  retains token debt.
- A room that never authenticates a host expires at 30 seconds, checked by the
  15-second sweep, allocation and first-host routing. Only a verified host route
  sets `hosted`. Existing hosted disconnect grace and 24-hour maximum remain.
- Mac room-allocation 429 gets the explicit busy/retrying state for both new and
  saved pairings. Later non-429 failures clear stale busy text; success restores
  the usual state without replacing a saved pairing or changing retry policy.

network sockets. These exercise HTTP admission, forged forwarding headers,

refill, the unchanged 100-room cap, occupied/idle source state, default entry 1025

reservation cleanup. Generated Duplex
streams exercise the real `ws.handleUpgrade` path, including socket 21 refusal,
another source, reconnection and malformed-handshake cleanup.

A mutation removing the connection reservation caused the real-upgrade assertion
to fail; original source was restored byte-for-byte and the focused suite passed again.
The first malformed-handshake fixture used a stream's closed flag too early;
it now waits for that stream's actual close event. The strict admission assertion
was retained. Syntax and diff whitespace checks pass.

## Automatic review disposition

The first-head review identified pressure from closed connection-only source
entries. The follow-up reclaims fully idle, fully replenished entries before
refusing a new source; a generated fixture checks immediate reuse while entries
with allocation debt or room/socket occupancy remain protected.
Disabling pressure reclamation fails that new assertion; restoring the server
byte-for-byte passes all 16 focused cases.

The review also requested verified end-client proxy identity and retention of
the old global allocation throttle. Proxy identity remains an explicit limitation:
no verified ingress rule is available, and the ticket/parent authorize socket
identity with no proxy configuration change. This must not be presented as
production end-user isolation behind Railway. The ticket explicitly replaces the
shared allocation-rate counter to provide independent budgets within remaining
global capacity; restoring that shared throttle would recreate the reproduced
cross-source refusal. The unchanged 100-room/300-TCP ceilings bound global live
resources, but coordinated sources can fill global rooms faster than under the
old shared throttle. Distributed exhaustion remains outside this mitigation.
