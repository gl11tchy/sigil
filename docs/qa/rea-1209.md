## Queue contract

Only notification and Live Activity push frames enter the queue. Host routing,
ready and matching token-registration completion gate writes. A single paced
drain checks pairing, connection, room and token context before and after writes.
Delayed callbacks cannot consume a newer drain or revive a stopped connection.
The queue holds at most20 entries. Updates coalesce for the same activity token;
an end supersedes prior updates and prevents resurrection. Ordinary entries can
be evicted at capacity, while accepted ends retain their reserved slots. At most20
active or pending-end activity registrations are admitted; a new registration
gets a clear busy reply when all slots are reserved.

Event bytes, sealed alert identity/issuance and absolute local deadline survive
waiting and reconnects. Local queue deadlines are300 seconds for alerts,60 for
updates and900 for ends; no send or reconnect renews them. These do not change
APNs storage headers. Normal old-room events are discarded when a room changes;
a same-pairing/activity end can follow a replacement room only after its current
token/environment is re-established. Different-environment ends wait without
blocking eligible frames behind them. Expiry bounds that wait.

An unauthenticated peer does not clear alerts. A valid authenticated phone command
clears ordinary queued alerts, while activities remain for delivery/reconciliation.
Explicit activity retirement can acknowledge a closed tab's pending end. Stop and
revoke clear queued work. Pairing changes discard prior activity registrations.
Terminal commands keep their existing direct dispatch and are never queued here.
