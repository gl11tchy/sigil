# REA-1210: preserve original APNs deadlines

Ticket: [REA-1210](https://linear.app/reasonable-glyph/issue/REA-1210/let-apns-keep-an-alert-briefly-when-the-phone-is-offline).
Base: `828a4b072819a719bcb0dcd3de095fcc5e38d30d`.

Before production edits, one generated fake-clock/held local APNs test failed:
the alert/update/end request expiration values were all undefined rather than
their original absolute deadlines. `apns.send` defaults those to header0. The
same focused test passes after the change. No real device/provider behavior or
unseen customer impact was observed.

Only two additive envelope fields expose original issuance/expiry in UTC integer
seconds. Mac admission aligns its immutable entry to the same fixed values as
the frame. The relay validates and copies timing before waiting; it never grants
fresh life at send time. Alert 300s/update 60s/end 900s are maximum lifetimes. Both
fields absent retains legacy expiration 0; partial/malformed timing rejects under
the existing invalid-push policy. Valid expired pushes answer `expired` without
APNs delivery. Sealed content/identity, client freshness, permissions, routing,
rate bounds and HTTP/2 retry policy are unchanged.

Activity payload timestamps preserve issuance (legacy admission), and FIFO
dispatch plus existing Mac end/coalescing protection remain. Alert collapse IDs
namespace room and tab with a 64-byte hash; activity events have no collapse key
that could replace an end. Tests cover original issue/queue/send times, shorter
valid deadlines, stale queued events, partial/noninteger/unsafe/future/overlong
timing, the existing 30s clock allowance, distinct rooms/tabs and legacy zero
storage. Local HTTP/2 capture checks actual zero/nonzero expiry headers using
generated keys. CI-only actual Mac/real-relay tests advance the owned fake clock
after admission and assert sealed issuance plus wire expiry stay fixed.

[Current Apple documentation](https://developer.apple.com/documentation/usernotifications/sending-notification-requests-to-apns?changes=_3)
was downloaded from the official Markdown endpoint. It confirms UTC epoch
seconds, zero storage, collapse-key limits and best-effort expiry, including
possible reordered/late delivery. Header acceptance is not physical delivery.

All 46 focused Node tests in relay-push, relay and apns passed, including existing
routing/privacy guards and actual loopback HTTP/2 zero/nonzero expiry headers.
Strict local Swift format, JavaScript syntax and diff checks passed. Mac tests
were added but have not been run locally. Both host and relay updates are required
for timed storage; older relays keep zero storage. The final observed exact-head
gate and counts are recorded in the PR. No local
AppTests/build, denied retries, personal data, process inventory, Apple/provider
calls, permission/encryption change, relay allocation/proxy-policy change or
HTTP/2 retry implementation. Physical phone delivery and rendered AX/window-ID
acceptance remain unobserved. Protected PR162 and earlier manual-review records
are preserved. Parent personal final code/CI review required before merge.
