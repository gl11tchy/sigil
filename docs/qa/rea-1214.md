## Accessibility fixture correction

[CI run 37973391928](https://github.com/gl11tchy-team/sigil/actions/runs/37973391928)
on `4f2166f7033f95e1d206ffde909e5f6748669001` passed the sidebar's data,
viewport and scrolling prerequisites. Its only Swift failures were the three
missing notice identifiers: the fixture collected an empty set. The unchanged
watcher recovery case passed in 0.213s; browser checks again passed 219 with one skip.

- The fixture queried the implementation `NSScrollView`, used an unordered
  window and discarded every child that did not formally conform to the full
  `NSAccessibilityProtocol`. An empty result from that traversal does not establish
  whether the product notices are accessible.
- Apple's [accessibility hierarchy guidance](https://developer.apple.com/library/archive/documentation/Accessibility/Conceptual/AccessibilityMacOSX/OSXAXmodel.html)
  distinguishes the exported hierarchy from implementation views. Its
  [custom-control guidance](https://developer.apple.com/library/archive/documentation/Accessibility/Conceptual/AccessibilityMacOSX/ImplementingAccessibilityforCustomControls.html)
  says accessibility getters can be exposed without adopting the full protocol.
  The SDK also declares `NSHostingView.accessibilityChildren()` as an override
  that supplies SwiftUI's exported children.
- The corrected fixture orders its own CI window onscreen, following the working
  `MacStartupTests` window/layout hosting pattern. Those tests do not prove
  SwiftUI accessibility export. It gives the host up to two seconds to expose
  children, and allows the run loop to process each scroll before reading the tree.
- Traversal now starts at the window root and reads supported public accessibility
  getters through Objective-C messaging. It accepts `NSObjectProtocol` objects,
  flattens ignored nodes with `NSAccessibility.unignoredChildren(from:)`, and
  guards cycles by object identity. It does not synthesize expected identifiers
  from model data or assume the native render-view tree is the accessible tree.
- All three final notice assertions remain, alongside the visible-row counts,
  200pt × 460pt fixture size, viewport comparison/minimum, positive scroll range
  and actual scrolling. Missing notices now print a bounded fixture tree
  diagnostic with object types, roles and identifiers. No product accessibility
  or layout code changed; notice exposure still requires CI execution.
- Final `swift build --build-tests --jobs 2`, changed-file strict formatting
  lint and `git diff --check` passed. Compilation used a throwaway home and a
  900-second bound. No app test or local UI inspection executed. Parser and watcher
  sources are unchanged; their passing results from the latest CI were not rerun
  locally for this fixture-only correction.
