## Implementation

RemoteControl exposes observable alertsArmed from enabled + paired + registered
alert token. Token changes are observed even while the phone status is unchanged.
RemoteIdleSleepWatch reads those inputs and effective per-tab evidence in one
observation, and a cancellable owned timer revisits only power policy. Timer
reviews do not accumulate additional Observation registrations. Shutdown cancels
pending callbacks and releases only this instance's assertion.

ProviderLifecycleJournal exposes a separate validated-work revision after its
existing current-file, session/turn/schema and process-lease validation succeeds.
Missing reads and invalidated ownership cannot provide power evidence. Quiet
polls retain the revision; duplicate or wrong-session/turn events cannot renew it.
TerminalTab exposes that evidence only for a running current watcher in Starting
or Working. The existing lifecycle states, binding rules and alert protocol are
unchanged. Codex catch-up counts only its final active work state.

The service keeps one assertion across connected/away/consumer transitions. Each
working-tab generation/progress revision has a monotonic two-hour power window.
Alert/connection changes and quiet polling do not renew that window. Create and
release failures are bounded by an injected-clock retry; a failed release keeps
ownership so reconnection cannot create a duplicate assertion. Two instances
operate independently. No global assertion or power-settings operation is used.
