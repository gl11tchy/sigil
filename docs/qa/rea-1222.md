## Bounded behavior

Cancel calls the non-revoking stop only while its captured generation is pending.
It does not read, save or clear pairing credentials, or post a revoke notice.
The view captures Cancel separately from Disconnect, so confirmation before a
queued click cannot turn that click into revocation. A completed pairing remains
live even if saving failed. An old rendered Cancel cannot stop a reopened attempt.

The connection failure path checks generation and cancellation before touching
watchers or sockets. A debug-only test pause forces an old failure to resume after
a saved connection reopens and verifies that connection still answers requests.
Explicit Disconnect and the failed-revoke retry retain their existing store-clear,
sticky failure and notification behavior. Authentication, origin matching,
Keychain access policy and pairing persistence implementation are unchanged.
