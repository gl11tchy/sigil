## Safety contract

`createAttempt` resolves the selected repository and exact HEAD, verifies that
the selected relative path is a tree in that commit, and checks name collisions
before creating parents. The checkout never substitutes for a missing subfolder.
The branch is compare-and-created from the validated commit. A successful receipt
records the repository, checkout, branch, original HEAD, chosen folder, directory
identities, Git administrative identities, and newly created parents.

Rollback is only for an attempt whose caller knows no process was dispatched.
It rechecks checkout/repository/Git identities, HEAD, branch, registered branch
checkouts, and tracked/untracked/ignored/submodule status. Worktree removal uses
no force option. Ref deletion compares the original commit so a moved branch
cannot be deleted. Parent removal uses identity checks and `rmdir`, which refuses
nonempty directories. A failed or uncertain check retains resources and reports
the complete recovery path and branch. Partial Git creation without a complete
receipt is retained and reported. This is not the user-confirmed task-finishing
workflow tracked independently in REA-1186.

The inline Mac surface, Options sheet and phone share this contract. Accepted
dispatches keep their workspace even if cancellation or a lost reply follows;
this change adds no retry or duplicate-dispatch behavior. Phone errors preserve
complete recovery paths instead of a 240-byte prefix; hook diagnostics are bounded
separately while their pipes are fully drained. Home repositories remain
recognized but default to Project folder. An optional per-project phone default
keeps native phone behavior aligned; explicit choices win and older Macs retain
the existing saved-default fallback. Web New Session options remain out of scope.

Git semantics: [worktree removal](https://git-scm.com/docs/git-worktree),
[compare-and-update/delete](https://git-scm.com/docs/git-update-ref),
[tree entries](https://git-scm.com/docs/git-ls-tree).

## Focused verification and limits

SigilKit fixtures cover missing/ignored and committed selected folders, aliases (including missing roots below a symlink),
unborn repositories, pristine removal, independent attempts, tracked/untracked/
ignored additions, changed HEAD/branch, shared branch checkouts, changed directory
identity, pre-existing collisions, possible process start, and locked cleanup
failure, including ref deletion failing after checkout removal. CI-only AppTests use bounded generated checkout hooks to hold creation,
cancel each entry point, deliver its late result, and verify cleanup. Dirty/locked
phone attempts retain and report recovery; a provider failure before dispatch
cleans up, a rejected dispatch cleans up, and an accepted late dispatch is retained
with one creation/launch. Folder overrides do not replace another folder's saved
default. Native phone tests cover legacy and explicit defaults.

in this document. Local strict formatting and diff checks run without building
