## Candidate

Successful scans retain added references while still folding legacy Sigil
worktree entries into their project. Folding deduplicates literal references;
distinct aliases and their pins survive temporary canonical convergence. Display
pin matching emits one row per canonical project while preserving all saved pins.
Directory existence/type and read/traverse
access determine the availability of added project projections. A missing,
unmounted, non-directory or inaccessible path is not evidence of deletion.

Unavailable home rows have text, a distinct mark and Retry, with context-menu
and accessibility actions. A focused unavailable project has a Retry notice.
Its New Session controls are unavailable until the folder is usable. Explicit
Remove/Archive retain their existing shared-list reload and filesystem behavior.
No saved-setting schema, provider identity rule or remote protocol field changes.
RemoteCommands receives the required shared projection callback only.

Availability is read during cached snapshot construction. Retry invalidates the
existing filesystem/canonical snapshot without starting a history traversal.
Filtered/focused projections preserve their prior ordering and timestamps.
The existing snapshot cache deadline, watcher behavior and performance checks
remain. The independent scan oracle carries the new field and retains its full
snapshot equality assertions.

The focused AddedProjectTests reuse ModelFixture without enlarging AppModelTests.
Generated fixtures cover absence/remount, non-directory replacement, denied
read/traverse access, Retry, worktree folding, lexical symlink reference survival
and retargeting/convergence/separation, unavailable Remove/Archive, files and unrelated pins, concurrent
settings-copy arrivals, and filtered/focused availability and dates. Only the
generated CI permission fixture changes its own access mode and restores it.
The accessibility value test checks the unavailable state without relying on colour.
Archive fixtures contain a generated conversation and use the same archiveOrRemove
dispatch as the row, checking archived metadata and retained source files. Remove
fixtures are chatless; both actions run with available and unavailable folders.

The normal [PR165](https://github.com/gl11tchy-team/sigil/pull/165) records the
final exact commit and integrated CI result; baseline failures are not approval
of the production candidate.
