## Change and reasoning

[SwiftPM 6.3.2's build-system selection](https://github.com/swiftlang/swift-package-manager/blob/swift-6.3.2-RELEASE/Sources/CoreCommands/Options.swift#L492-L509)
switches multiple architectures to XCBuild even when `native` is requested.
The new helper invokes native SwiftPM once per architecture with separate
scratch paths, verifies each product's slice, then joins and verifies Sigil and
sigil-mcp. This follows [Apple's documented lipo assembly approach](https://developer.apple.com/documentation/apple-silicon/building-a-universal-macos-binary).
It avoids this observed XCBuild path; no Metal/toolchain installation or SDK
permission change is attempted.

Each output directory starts without products. Cached slice executables are
removed before their compile, preventing a missing/failed build from reusing
them. A failed slice, missing executable, wrong architecture or failed merge
removes partial assembled outputs. Existing output products are refused and
preserved. Build-app uses an owned temporary products directory and keeps its
existing opt-in local thin fallback; CI no longer opts in.

CI now builds, checks both architectures in the actual bundle, smoke-launches
and packages the release on PRs too. The existing seven-day private artifact
upload can retain the candidate for independent review. Publication remains
push-to-main-only; token permissions, signing/notarization policy, release
pruning and the 45-minute timeout are unchanged. No separate public
distribution is introduced.

The MCP entrypoint is a byte-identical rename to `SigilMCP.swift` (SHA256
`111e10ef3aa265fd2b6d3e46dc9a62404aabb8197ddf31228e30d2131a5b1af5`).
README and the two site architecture sentences describe the universal
candidate; provider/site functionality is outside this ticket.

## Acceptance and limits

- Stop before merge for parent personal exact-final-head source/ticket/comment
  review and required passing CI. Inspect both architectures in the exact
  candidate ZIP before handoff; do not infer them from a fake-tool test.
- Actual main publication/universal shipped artifact remains pending approved
  merge and main CI. Currently installed build426 and official build689.1 are
  arm64-only; this source change is not proof that a new artifact or product site
  is already deployed.
- CI runs on arm64. x86_64 architecture presence is separate from execution on
  Intel hardware, which is unverified. A three-second arm64 launch does not
  prove the Intel slice or complete UI/provider behavior.
- No local native build/test, listener/process enumeration, held UI route,
  personal provider data, real credentials, OS/access/signing-policy change,
  hosted deployment, app replacement or extra worker. Held PRs162/183/191/192
  and installed426 remain unchanged. REA-1224/1230/1254 remain separate.
