## Behavior and regression coverage

`ProviderInstallation.timedOut` distinguishes deadline expiry from an executable
that is missing, invalid or cannot start. A timeout never authorizes launch.

`ProviderChecks` owns one cancellable timer for all providers, with the same
clock/probe generation fences as entry/Settings checks. It retries only typed
timeouts with 5/15/45-second delays between attempts (normally t+5, t+20, t+65
after a timeout, excluding probe duration). The next activation may advance one
pending attempt; bursts do not reset the three-attempt budget. Missing/invalid
failures receive no automatic retries. An exhausted timeout says “Version check
timed out” and provides Check Again through the existing New Session tile or
Grok Settings check. Explicit checks start a new bounded sequence.

Every current completed batch notifies AppModel. A ready saved prefix restores
without opening New Session; a later success cannot overtake an earlier pending
retry. Deferred references keep their saved positions/selection through
exhaustion, and a later successful explicit check inserts the recovered tab
before later restored peers. Existing identity comparisons remain unchanged.

CI-only `ProviderLaunchAvailabilityTests` inject the actual probe, clock and
sleep scheduling, including delivery of canceled timers, to cover:

- One timeout followed by success restoring a saved native tab.
- Exact backoff, exhaustion, truthful state and one-click manual recovery.
- No automatic retry of missing/invalid installations.
- Forced refresh and executable change during waiting and running retries.
- Activation bursts without duplicate probes or renewed budgets.
- Two providers completing separately, in either order, including exhaustion,
  manual recovery, exact/legacy selection and repeated restoration calls.

Kit tests cover synchronous/asynchronous timeout flags, missing/invalid failure
classification and launch rejection for a contradictory timeout result.
Ordinary exact-head CI results are recorded on the ticket's PR. No native
AX/layout, actual cold-login timing, customer CLI/version or runtime impact is
claimed.
