# REA-1255 sidebar snapshot reuse

Ticket: [REA-1255](https://linear.app/reasonable-glyph/issue/REA-1255/stop-rebuilding-the-900-chat-sidebar-snapshot-on-every-hover-and-arrow).
Base: `cb3f89df644759253dadfab82b25a66e2c7fec08`.

Rendering and keyboard events share one snapshot for equal inputs within one
second, measured by an injectable monotonic clock. Session values, query,
surface, names, pins, archives, added folders, all four filters, Sigil membership
and tab identity participate in the key. Row activity stays independently
observable. Expiry also clears canonical/ephemeral classification caches.

The visible sidebar owns a cancellable passive FSEvents stream. Folder identity,
symlink parents, Git marker replacements and worktree `commondir` changes schedule
observable invalidation at the snapshot deadline (stream latency is 0.25 seconds).
An unchanged watched sidebar performs no periodic full-list rebuild. A failed
or partially covered stream uses one-second refreshes while the view remains visible.
The watch-path identity is computed with the snapshot and reused on hover;
startup/remount reconciles changes made while observation was absent. Missing roots
are watched through existing parents; this mechanism neither scans provider
history nor prunes saved projects. Existing history authority fences remain intact.
Canonical OS aliases preserve the watched symlink's own name. With worktree
sessions hidden, classification paths without a known Git boundary retain
fallback for new ancestor markers; lexical scratch locations need no Git work.
The canonical watcher path uses POSIX resolution of the nearest existing ancestor:
Foundation can retain `/var` while FSEvents reports `/private/var`. Generated
existing/missing-path regressions cover that distinction without loosening matching.

## Measurement method

The CI-only `SigilSidebarFixtureHost.app` hosts the real SidebarView in a
200 × 460 window with the host's real reduced-motion setting (recorded, not
overridden). It seeds 1,000 generated Grok summary rows
in one temporary project, shows worktree sessions (temporary paths would otherwise
be filtered out), opens Recents, and invokes the callback used by row `onHover`
for 20 valid row IDs. Each callback must render its highlight before advancing.
The wall-clock sweep excludes fixture seeding and initial layout and includes
async render scheduling. The DEBUG-only probe is absent from release builds.

This programmatic callback sweep measures sidebar state churn. It does not
measure physical pointer delivery, hover hit-testing, frame latency, hidden
worktree stat costs, unavailable volumes, or customer histories. Rows beyond the
small viewport are driven by ID rather than physical scrolling. No customer
performance claim follows from this fixture.

## Checks and limits

- Direct type-check and Address Sanitizer checks of the two watcher sources pass
  generated alias/missing-root planning and source-churn filtering. An initial
  unsafe root-watch plan was caught and corrected; no stream watched `/`.
- Local FSEvents cannot start in the restricted environment; callback delivery,
  quiet Observation invalidation and cancellation require CI validation.
- Focused CI tests cover reuse/deadline and watch-path reuse, visibility-key changes,
  learned tab identity, independently read activity, symlink grouping, quiet
  invalidation, partial-watch fallback and cancellation. The existing render-count
  regression asserts the new reuse contract; the original viewport/accessibility
  fixture remains required.
- Local SwiftPM/Observation builds and process inspection remain excluded after
  earlier automatic approval denials. AppTests and hosted windows run only in CI.
- No personal histories, daily app replacement, access changes or merge. Parent
  personal final-diff review and exact-head CI are required before merge.
