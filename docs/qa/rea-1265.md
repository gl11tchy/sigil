# REA-1265: preserve completion tracking across Return

Ticket: https://linear.app/reasonable-glyph/issue/REA-1265/keep-a-codex-turns-completion-when-return-is-pressed-mid-turn

Base: `eaa36d06fbd05c19ed1d98f5829505b49bb08988`. Branch:
`fix/rea-1265-preserve-turn-watcher`. REA-1211 is Done; REA-1218 remains
separate, so this change uses resumed Codex sessions with validated metadata.

Current code cancels the watcher and opens a fresh journal at the current end
on each Return. That discards the active Codex turn ID and ignores its later
completion. The persistent poll loop already supports subsequent turns.

The correction preserves the current watcher/journal across submissions,
including its offset, file identity, active turn and duplicate-event memory.
Codex input remains a submission hint until a provider event confirms work.
Explicit watcher generations fence cancellation, interruption and process
replacement, including synchronous callbacks during poll-batch application.
Existing capability, metadata/session/turn validation and Grok chunk semantics
remain required.
