# REA-1266 verification record

2026-10-11. Base: `96d48415e16b673591c0ddf1158e96f6b5ef1f39`.
All data below is generated Claude-format JSONL in isolated throwaway homes.
It proves parser behavior, not a captured live CLI incident or customer impact.
No personal Claude/Codex transcripts, credentials or provider calls were used.

The baseline direct production-source harness reproduced a lost rename at byte
717,045 in a 923,107-byte transcript. A further 1,049,570 generated bytes left
the row on its first prompt. A small transcript accepted the identical rename.

The implementation streams Claude records and caches only bounded display fields,
record framing progress and fixed continuity anchors. Empty renames restore the
first prompt. Complete final JSON without a newline remains compatible without
prematurely committing its line. Oversized records discard through the newline;
their notice survives an unchanged cache hit. Interrupted/read-racing scans do
not publish partial cache progress or clear uncertain coverage.

Local validation uses the existing direct `swiftc` production-source harness,
15 production files, including the modified scanners, no stubs and normal sandboxing.
New Swift Testing method bodies are exercised as plain assertion functions with
the same fixture helpers; this is not a local Swift Testing framework run.
The 19 generated cases passed: middle rename and byte-counted append/newest rename;
four marker/JSON/UTF-8 chunk sizes; partial UTF-8 across scans and explicit clear;
legacy EOF projection; six replacement/truncation/rewrite cases; oversized-record
discard/recovery; cold/warm cancellation; two during-read mutations; and a middle
identity conflict. The smoke fixture measured 1,049,570 appended bytes and 8,407
continuity-validation bytes, without streaming old transcript records again.
Read requests stay at or below 512 KiB (64 KiB for transcript streaming), beneath
the 1 MiB acceptance ceiling. Partial-record storage is capped at 512 KiB;
prefix/tail samples are at most 4 KiB each and record digests have five field slots.

Continuity limits: the fixed prefix/tail and retained-field anchors are sampled
verification, not a fingerprint of every prior byte. The growth-rewrite fixtures
change the retained middle rename, first identity/prompt, or old tail. An arbitrary
rewrite outside these anchors can evade detection; proving every old byte would
require reading the old prefix again. `ignoringCache` performs a full revalidation.
This limitation is called out for parent review rather than claimed as complete
detection of arbitrary old-prefix edits.

The existing 14 production-scanner compatibility groups also run on the changed

protection versus independently deleted rows, root/read uncertainty, unsupported
Grok summaries and coordinated root observation. Codex transcript/index windows,
REA-1216's independent tab-binding identity, and parked PR150's provider UI remain
outside this change.
