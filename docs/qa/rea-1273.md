# REA-1273: Finder folder paths

Ticket: https://linear.app/reasonable-glyph/issue/REA-1273/paste-a-dropped-or-copied-finder-folder-as-its-path

Base: `f0e319a818dda39f7165d90e5c050cf35db724fe`. Isolated branch:
`fix/rea-1273-finder-folder-paths`.

The current directory rejection causes folder drops to be refused and Finder
copies to take the basename text branch. The correction keeps existing
files and directories in the same standardized absolute-path list. It does
not enumerate folders, read their contents, upload them or change phone uploads.
The existing control rejection, shell quoting, Finder order, 16-item cap and
terminal paste framing remain the policy.

## Evidence

The [test-only baseline](https://github.com/gl11tchy-team/sigil/actions/runs/38325625030)
on `6689bb36f8834cf95efb91b6275afe4675c1f370` completed 37 XCTest cases
with zero failures and 1,225 Swift tests in 108 suites. Four focused tests
recorded eight issues: copied folders sent their basename, mixed drops omitted
folders, the mixed 16-item list omitted directories, and the standardized/symlink
folder paths were refused. The unsafe-folder rejection case passed. These are
synthetic-fixture observations, not measurements of customer conversations.

The earlier run stopped at a test-helper compile error; its AppKit legacy
promised-file method needed `override`. That declaration was corrected before
observing the baseline above. No production change was made for that repair.

The final candidate also exercises a single-folder drop in both paste modes,
and requires the real drag acceptance handlers to return `.copy` for a
folder-only pasteboard. The PR's exact-head CI check is the final integrated gate;
its result and source commit are linked in the PR description.

The new tests use generated temporary files/folders, named pasteboards and a
raw-mode PTY sink. They exercise the real copy/drop handlers without windows or
input to another application. They require the copy operation, exact mixed path
order, named symlink path, literal quoting and exact bytes with bracketed paste
both enabled and disabled. No newline or Return is appended. Folder controls
must refuse the drop and send no input through Finder's text fallback. Existing
image/phone cache tests remain intact.
