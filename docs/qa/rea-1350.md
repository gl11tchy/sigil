# REA-1350 verification

[Linear issue](https://linear.app/reasonable-glyph/issue/REA-1350/make-the-sidebar-divider-track-horizontal-dragging-reliably)

## Change and cause

The generated current-main reproduction showed moving local gesture coordinates
and competing server-side window dragging. The shared seam captures on mouse-down,
uses screen positions from actual NSEvents, consumes movement at bounds for immediate
reversal, and adopts the visible width after layout changes. The existing WindowColumns
solver supplies narrower physical limits. Both 9-point seam targets remain above their
neighbors. Keyboard and AX adjustment keep their 20-point steps and value-editing focus.

Capture starts focus without writing width. A saved 430-point sidebar rendered at a
218-point cap therefore survives a click and stationary drag. Horizontal movement
updates the preference from the rendered width.

WindowChrome disables competing automatic background capture. Small native background
views in non-interactive header spaces and read-only folder labels call NSWindow.performDrag. Their bounds define
the input surface; they accept the first mouse event of an inactive window. LaunchCanvas
also retains background dragging. A whole-window SwiftUI WindowDragGesture was removed;
even narrowing it to header spacers still intercepted a generated terminal mouse-down
in a native check. The native background views passed the same selection check.

## CI failure investigation and coverage

[Initial CI38198020570](https://github.com/gl11tchy-team/sigil/actions/runs/38198020570)
failed: three rendered-seam width assertions stayed 272, and the existing filesystem
observation test failed its initial quiet assertion before the symlink changed.
The remaining checks did not run. These failures were investigated, not classified
as pre-existing or waived.

The rendered event helper had called NSApp.sendEvent directly. Apple's
[currentEvent documentation](https://developer.apple.com/documentation/appkit/nsapplication/currentevent)
identifies it as the last event retrieved from the application queue. The revised helper
posts and retrieves each event before dispatch and requires the expected current event.
All original width assertions remain. The filesystem test now requires a bounded quiet
startup period before its original steady-state, retargeting and cancellation assertions;
coalesced fixture-creation events can arrive after mounting. A recurring one-second
invalidation cannot satisfy the 1.3-second startup quiet requirement.

Thirteen divider tests preserve substantive coverage: nine Capture tests run in
the serial Swift Testing suite; four rendered seam/capped-click/terminal/Notes
cases now run in the existing CI-only SwiftUI app host. The host requires a
running AppKit event loop, uses generated history, fake installations/shells,
and validates posted-event number, window, type, timestamp, modifiers and coordinates.
AppKit can copy a posted NSEvent, so Swift object identity is not used. Fixture
windows disable animation to keep presentation from remapping coordinates. Selection gestures
queue the complete sequence before dispatch so NSTextView can finish nested
tracking. The hosted result must contain six passed fixtures, no failures or skips
(the existing two sidebar fixtures plus four interactions).

CI38200416521 stopped at a missing terminal-view cast; CI38201463532 stopped at a
nested #require macro. Both compile errors were corrected without weakening
selection or stationary-window assertions. CI38202086650 was green at the job
level but its completed log recorded a rendered-seam event mismatch and stopped
Swift Testing output during the next test without a completion summary. That green
check is not valid passing-test evidence. No exit, signal or crash reason was logged,
so none is claimed. The CLI test helper was manually pumping AppKit; the rendered
cases now let the existing SwiftUI app host own normal event processing.

Scripts/verify.sh now checks both command status and the complete Swift Testing
log. Recorded issues, failed tests/suites, missing completion, duplicate summaries
or tests starting after completion fail the gate. Seven generated Python tests
cover these cases; the guard rejects the actual false-green CI log. Later hosted
sidebar, formatting, debug bundle/smoke and iPhone checks from that run passed,
but do not substitute for incomplete Swift test execution.

CI38204205142 completed all 1,220 Swift tests and 37 XCTest cases; the completion
guard confirmed. All four new hosted cases then failed the input helper's Swift
object-identity assertion. The saved xcresult showed identical event fields for
capped-click and terminal input in different objects, plus coordinate differences
for seam and Notes input. The delivery helper now checks the actual event envelope
and fixture windows disable animation; behavior expectations remain unchanged.
The hosted runner now prints its saved summary even on xcodebuild failure.

No SigilAppTests compilation/execution was attempted locally. The earlier local
compile rejection by automatic approval review remains honored. Exact-head CI,
completed tests and parent personal review are required before merge.

## Limits

Native evidence covers the installed Mac, arm64, one display and dark appearance,
with generated empty history and finite fake-shell output. The folder-label probe
preserved movement but produced 20 points for a 30-point path; its strict comparison
failed and remains a review limitation. A separate populated
history attempt became AX-unresponsive during loading (-25204); its normal quit was
requested, without force termination. It supplied no Notes-drag result. The generated
Notes selection test runs only in CI. This record does not prove customer impact,
full VoiceOver narration, multi-display behavior, or macOS 14 runtime behavior.

Compatibility-warning presentation remains REA-1351. No daily app replacement,
merge, personal-history inspection, or next-ticket work occurred.
