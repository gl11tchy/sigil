# REA-1350 verification

[Linear issue](https://linear.app/reasonable-glyph/issue/REA-1350/make-the-sidebar-divider-track-horizontal-dragging-reliably)

## Change and cause

The generated current-main reproduction showed moving local gesture coordinates
and competing server-side window dragging. The shared seam now starts capture
on mouse-down, uses screen positions from actual NSEvents, consumes movement at
bounds for immediate reversal, and adopts the visible width after layout changes.
The existing WindowColumns solver supplies tighter limits for narrow windows.
Both 9-point seam targets remain above their neighbors. Keyboard and AX adjustment
keep their 20-point steps and value-editing focus.

WindowChrome disables competing automatic background capture. Non-interactive
window content uses Apple's WindowDragGesture on macOS 15 and later, with the
public NSWindow.performDrag fallback on macOS 14. Child seam gestures have higher
priority. LaunchCanvas retains background dragging too. The source does not add
native overlays or change global window movement flags during capture.
